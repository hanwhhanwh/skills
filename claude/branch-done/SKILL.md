현재 브랜치의 작업을 마무리하고, 결과 문서를 지정한 폴더에 정리합니다. 아래 단계를 순서대로 수행합니다.

## 사전 점검

폴더, 브랜치, 원격 저장소 확인(아래 첫 세 항목)에 실패하면 아무 작업도 하지 않고 이유를 보고한 뒤 멈춥니다. GitHub·gh 조건은 PR 단계만 건너뛰게 할 뿐 멈추지 않습니다.

- 인자가 없으면 저장할 폴더를 요청합니다. 폴더가 없으면 추측해서 만들지 말고 사용자에게 확인합니다.
- `git branch --show-current`로 브랜치명(`<브랜치>`)을 구합니다. 비어 있거나(detached HEAD) 기본 브랜치이면 멈춥니다. 파일명에는 브랜치명의 `/`를 `-`로 바꿔 씁니다.
- 기본 브랜치(`<기본>`)는 `git symbolic-ref --short refs/remotes/origin/HEAD`에서 `origin/`을 뗀 값으로 정하고, 구할 수 없으면 `main`을 씁니다. `origin` 원격이 없으면 멈춥니다.
- PR 단계 수행 여부(`<PR 진행>`)를 정합니다. 아래 조건을 모두 만족할 때만 PR 단계(6·7단계)를 수행하고, 하나라도 맞지 않으면 그 이유를 기록해 두고 PR 단계만 건너뜁니다.
  - `git remote get-url origin`이 `github.com`을 가리킵니다.
  - `gh`가 설치되어 있고 `gh auth status`로 로그인이 확인됩니다.
- `<PR 진행>`이면 이 브랜치에 이미 열린 PR이 있는지 `gh pr view --json number,state,url`로 확인합니다. 열린 PR이 있으면 새로 만들지 않고 그 PR을 갱신·병합 대상으로 씁니다. 이미 병합되었거나 닫힌 PR만 있으면 사용자에게 확인합니다.
- 시작 시각을 `<yyyymmdd>_<hhnn>`(로컬 시간, 예: `20261125_1034`)으로 한 번만 구해 모든 단계에서 같은 값을 씁니다.
- 11·12단계에서 만들 파일이 이미 있으면 덮어써도 되는지 미리 한 번에 확인합니다. 2·8단계 문서는 덮어쓰지 않고 갱신하며, 10단계는 스크립트가 항상 새로 씁니다.

korean-review와 chat-history 스킬은 호출하지 않습니다. 이 스킬에 포함된 사본(`references/korean-review.md`, `scripts/chat_history.py`)으로 같은 작업을 직접 수행하므로 두 스킬이 설치되어 있지 않아도 동작합니다.

## 절차

### A. 커밋과 push

1. 순차 커밋
   - `git status`와 `git diff`로 커밋되지 않은 변경을 확인합니다. 없으면 이 단계를 건너뜁니다.
   - 변경을 논리 단위(기능, 수정, 문서 등)로 나누고, 의존 관계 순서대로(예: 라이브러리·스크립트 → 이를 쓰는 코드·설정 → 문서) 커밋 계획을 세웁니다. 단위가 하나뿐이면 한 번에 커밋합니다.
   - 저장 폴더가 저장소 안에 있으면 그 폴더의 산출물은 커밋 대상에서 뺍니다.
   - 비밀번호, 접속 키, `.env`, 인증서처럼 민감해 보이는 파일이 있으면 커밋 대상에서 빼고 알립니다.
   - 커밋 메시지는 저장소의 기존 형식(예: `feat(scope): ...`)을 따르고, 대화 중 안내받은 커밋 서명 문구가 있으면 끝에 붙입니다.
   - **확인 1:** 커밋 순서별로 파일 목록과 커밋 메시지를 보여 주고 승인을 받은 뒤, 파일을 지정해 `git add <파일>`과 `git commit`을 순서대로 실행합니다. `git add -A`나 `git add .`은 쓰지 않습니다.
2. PR 메시지 작성 — `<브랜치>-pr.md`
   - `git log <기본>..HEAD`, `git diff --stat <기본>...HEAD`로 변경 내용을 확인합니다.
   - 첫 줄은 `# <PR 제목>`으로 쓰고, 제목은 저장소의 기존 커밋·PR 제목 형식을 따릅니다.
   - 본문에는 요약, 주요 변경 사항, 테스트·검증 방법을 적습니다. 대화 중 안내받은 PR 서명 문구가 있으면 본문 끝에 붙입니다.
   - 파일이 이미 있으면 기존 내용을 유지한 채 갱신합니다.
3. PR 메시지 교정 — `${CLAUDE_SKILL_DIR}/references/korean-review.md`를 읽고 그 규칙과 절차에 따라 `<브랜치>-pr.md`를 교정합니다. 그 문서의 '교정 대상' 절에 들어갈 값은 이 단계의 대상 파일입니다.
4. **확인 2:** 아래 내용을 한 번에 보여 주고 승인을 받습니다. 승인하지 않으면 여기서 멈추고, 이미 만든 커밋과 `-pr.md`는 그대로 둡니다.
   - push할 원격 저장소와 브랜치, 커밋 목록
   - `<PR 진행>`이면 PR 제목과 본문(`-pr.md` 내용), 대상 브랜치(`<기본>`), 병합 방식(`--merge`), 병합 후 삭제할 로컬·원격 브랜치
   - `<PR 진행>`이 아니면 PR 단계를 건너뛰는 이유
5. 브랜치 push — `git push -u origin <브랜치>`. 강제 push(`--force`)는 하지 않습니다. 거부되면 멈추고 보고합니다.
   - push 직후 8단계에서 쓸 정보(`git log <기본>..HEAD`, `git diff --stat <기본>...HEAD`)를 확보해 둡니다.

### B. PR (GitHub 저장소이고 gh가 있을 때만)

`<PR 진행>`이 아니면 6·7단계를 건너뛰고 8단계로 갑니다. 브랜치는 그대로 두고, 보고에 PR을 직접 만들어야 한다고 적습니다.

6. PR 생성 — `-pr.md`의 첫 줄(`# ` 제외)을 제목으로, 둘째 줄부터를 본문으로 씁니다.

   ```bash
   tail -n +2 "<폴더>/<브랜치>-pr.md" | gh pr create --base <기본> --head <브랜치> --title "<PR 제목>" --body-file -
   ```

   이미 열린 PR이 있으면 `gh pr edit <번호> --title "<PR 제목>" --body-file -`로 제목과 본문을 갱신합니다. PR 번호와 URL을 확보해 둡니다.
7. 병합과 정리
   - `gh pr merge <번호> --merge`로 병합합니다. CI 실패, 리뷰 필요, 충돌 때문에 병합할 수 없으면 `--admin` 등으로 우회하지 말고 이 단계를 멈춘 뒤 8단계로 갑니다.
   - `git switch <기본>` 후 `git pull --ff-only`로 최신화합니다.
   - `git branch -d <브랜치>`로 로컬 브랜치를 지웁니다. 병합되지 않았다고 거부되면 `-D`로 강제하지 말고 보고합니다.
   - `git push origin --delete <브랜치>`로 원격 브랜치를 지웁니다. GitHub 설정으로 이미 지워졌으면 건너뜁니다.

### C. 기록

8. 작업 내역 문서 갱신 — `<브랜치>.md`
   - 5단계에서 확보한 커밋·변경 파일 정보와, 현재 세션에서 논의·결정한 내용(배경, 결정 사항과 이유, 검증 결과, 남은 과제)을 함께 정리합니다.
   - PR 번호·URL과 병합 결과를 적습니다. PR 단계를 건너뛰었거나 병합하지 못했으면 그 이유를 적습니다.
   - 파일이 이미 있으면 기존 내용과 구조를 유지한 채 새 내용만 반영합니다. 없으면 새로 작성합니다.
9. 작업 내역 문서 교정 — 3단계와 같은 방법으로 `<브랜치>.md`를 교정합니다.
10. 채팅 기록 저장 — `<브랜치>-chat.md`. `python`이 없으면 `python3`을 사용합니다.

    ```bash
    python "${CLAUDE_SKILL_DIR}/scripts/chat_history.py" "<폴더>/<브랜치>-chat.md" "${CLAUDE_SESSION_ID}"
    ```

    프롬프트에 비밀번호, 접속 키, 개인정보처럼 보이는 내용이 있으면 내용을 인용하지 말고 종류만 알린 뒤 마스킹 여부를 묻습니다.
11. 대화록 저장 — 내장 `/export` 명령은 스킬에서 실행할 수 없으므로 스크립트로 대신 저장합니다.

    ```bash
    python "${CLAUDE_SKILL_DIR}/scripts/export_session.py" "<폴더>/<브랜치>-claude-<yyyymmdd>_<hhnn>" "${CLAUDE_SESSION_ID}"
    ```

    스크립트 출력의 마지막 줄이 현재 세션의 transcript 경로입니다. 12단계에서 이 경로를 씁니다.
12. transcript 압축 — `<브랜치>-<세션 UUID>.jsonl.7z`. 7z를 최고 압축률로 사용합니다.
    - `7z`가 PATH에 없으면 `C:/Program Files/7-Zip/7z.exe`를 사용하고, 둘 다 없으면 이 단계를 건너뛰고 보고합니다.
    - 대상 파일이 이미 있고 덮어쓰기 승인을 받았으면 먼저 지운 뒤 압축합니다. 그대로 두면 7z가 기존 압축 파일에 내용을 추가합니다.

    ```bash
    7z a -t7z -mx=9 "<폴더>/<브랜치>-<세션 UUID>.jsonl.7z" "<transcript 경로>"
    ```

    transcript에는 이 단계까지의 기록만 담깁니다.

## 보고 형식
